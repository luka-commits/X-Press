  <name>Task 1: Add Reports KPI order list query functions</name>
  <files>src/lib/reporting-queries.ts</files>
  <action>
Add query functions to reporting-queries.ts following the existing KPIOrderItem pattern from dashboard-queries.ts:

1. **Import and reuse KPIOrderItem type** from dashboard-queries.ts (re-export for convenience)

2. **getProblemOrders(date: Date)** → KPIOrderItem[]
   - Query: istStatus = 'problem'
   - Sort: liefertermin ASC
   - Returns same shape as other KPI queries (auftragsnummer, kunde, produkttyp, liefertermin, tageUebrig)

3. **getOldestOrders(date: Date, limit: number = 10)** → KPIOrderItem[]
   - Query: versandStatus != 'versendet' (open orders)
   - Sort: liefertermin ASC (oldest first)
   - Limit to top N oldest orders
   - Purpose: Shows which orders have been waiting longest

4. **getTomorrowOrders(date: Date)** → KPIOrderItem[]
   - Query: liefertermin = tomorrow (date + 1 day, full day range)
   - Filter: versandStatus != 'versendet'
   - Sort: liefertermin ASC

5. **getOrdersByStage(stage: string, date: Date)** → KPIOrderItem[]
   - Stage values: 'offen', 'in_produktion', 'fertig', 'versandbereit', 'versendet', 'problem'
   - Logic matches getFunnelData() categorization:
     - 'problem': istStatus = 'problem'
     - 'versendet': versandStatus = 'versendet'
     - 'versandbereit': versandStatus = 'versandbereit'
     - 'fertig': istStatus = 'fertig'
     - 'in_produktion': istStatus = 'in_produktion'
     - 'offen': no istStatus AND versandStatus NOT in ('versandbereit', 'versendet')
   - Include Kunde join for kunde name
   - Sort: liefertermin ASC

Use same date handling pattern as dashboard-queries.ts (startOfDay, differenceInDays for tageUebrig).

<task type="auto">
  <name>Task 2: Create Reports KPI orders API endpoint</name>
  <files>src/app/api/reports/kpi-orders/route.ts</files>
  <action>
Create new API endpoint following the pattern from /api/dashboard/kpi-orders:

**GET /api/reports/kpi-orders**

Query params:
- type (required): 'problem' | 'oldest' | 'tomorrow' | 'stage'
- stage (required if type='stage'): 'offen' | 'in_produktion' | 'fertig' | 'versandbereit' | 'versendet' | 'problem'
- date (optional): ISO date string (YYYY-MM-DD), defaults to today
- limit (optional, only for type='oldest'): number, defaults to 10

Response format (same as dashboard kpi-orders):
```typescript
{
  type: string;
  orders: KPIOrderItem[];
  count: number;
  date: string;
  stage?: string;  // included when type='stage'
}
```

Implementation:
1. Parse and validate type parameter
2. For type='stage', validate stage parameter
3. Parse date with T12:00:00 suffix (timezone-safe pattern from phase 26)
4. Call appropriate query function
5. Return consistent response shape

Error handling:
- 400 for missing/invalid type
- 400 for missing stage when type='stage'
- 400 for invalid stage value
- 400 for invalid date format
- German error messages (consistent with project)

Add `export const dynamic = 'force-dynamic'` for real-time data.

  </verify>
