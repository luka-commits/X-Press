<task type="auto">
  <name>Task 1: Create search API route</name>
  <files>src/app/api/orders/search/route.ts</files>
  <action>
Create GET /api/orders/search endpoint:

1. Accept query param `q` (search term, minimum 2 characters)
2. Search across: auftragsnummer (contains), kunde.firma (contains), kunde.name (contains), produkttyp (contains)
3. Use Prisma OR query with `mode: 'insensitive'` (same pattern as /api/orders)
4. Return only active orders (`status: 'aktiv'`)
5. Limit to 10 results, ordered by liefertermin ASC
6. Return minimal fields: id, auftragsnummer, produkttyp, liefertermin, kunde (firma, name)

Response format:
```json
{
  "results": [
    {
      "id": 123,
      "auftragsnummer": "GP25-7647",
      "produkttyp": "Broschüren",
      "liefertermin": "2026-01-20",
      "kunde": { "firma": "ABC GmbH", "name": "Max Müller" }
    }
  ]
}
```

Error handling:
- Return empty array if `q` is missing or < 2 chars
- Return 500 with JSON error on database errors
  </action>
  <verify>
curl "http://localhost:3000/api/orders/search?q=GP" returns JSON with results array
curl "http://localhost:3000/api/orders/search?q=a" returns empty results (too short)
  </verify>
  <done>
- Endpoint responds with matching orders
- Search works across auftragsnummer, kunde, produkttyp
- Results limited to 10, ordered by liefertermin
  </done>
</task>
